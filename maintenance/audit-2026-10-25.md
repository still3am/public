# PUBLIC audit — October 25, 2026

## Scope and evidence

Reviewed the route inventory and source paths for all 33 page components, their shared session/catalog/library infrastructure, and existing feature regression coverage. This was a code and automated-test audit. A live browser attempt at https://publicnet.base44.app returned an App not found response; the Base44 connector reported ready. These observations do not establish whether the site is unavailable in the user's browser. No signed-in desktop/iPhone walkthrough, physical audio-output test, production upload, account deletion, notification delivery, or offline browser-storage test was completed in this pass.

## Fixes

- Session checks now refresh approved creator roles and revocations in already open sessions, on focus, reconnect, and the existing interval. Slow auth/verification responses cannot restore a logged-out account. Profile badges track refreshed roles.
- Confirmed album-library saves now emit the same per-song automatic offline-download events as individual saves, including partial albums. Existing songs do not emit duplicate additions.
- Offline errors are visible even when cloud-list loading failed before a pending count was available. Explicit retry clears the per-song retry delay; background retry throttling remains in place.
- Recent and chart pages refresh on catalog invalidation rather than retaining stale entries after catalog/access changes.
- Artist applications use complete admin pagination, stale-load guards, and a retry state that blocks submission when application status could not be read. Both supported SDK response shapes are accepted; malformed responses fail visibly.
- Album identification clears its busy state when a new list has no missing album data.
- Restored the song-detail lyrics match button so the mounted fallback dialog is reachable. Automatic measured-duration matching remains the primary path.
- Queued uploads recheck the actual account ID before file transfer, not only whether the current account has a creator role.
- Native admin suggestion completion sends the existing author/supporter notifications, checks the saved status, reports partial delivery, and deduplicates retry delivery. Admin list refreshes cannot overwrite an in-progress status action.
- Collaborative playlist listing uses canonical membership, including private playlists. Server checks exclude revoked memberships and blocked/unavailable owners. Owned playlists remain available if shared-list recovery fails; a partial error is shown. No database permission rules were relaxed.
- Admin account deletion now calls the ordered account-and-reference cleanup rather than deleting only the User record. Server authorization and confirmation are required; regular/suspended callers cannot delete other accounts. Cleanup failures retain identity for retry. Artist applications are included in account cleanup. The admin member list directs self-deletion to Profile settings. No live deletions were performed.
- Corrected the privacy page's description of offline files retained after sign-out.

## Continued code audit

- Activity read flags now use a narrow native database client with recipient checks and confirmed post-write reads. Mark-all drains bounded batches and leaves notifications arriving after the click unread. An ignored write is reported as a failure; a lost response is reconciled against stored state. No notification text or recipient fields are changed by these helpers.
- Artist release read flags are grouped by the listener's own subscription and confirmed before updating the UI. Old pending catalog reads cannot resurrect unread flags after a save. Catalog invalidation removes withdrawn release alerts rather than waiting for a cached refresh.
- Mark-all takes its action lock before awaiting release updates, preventing duplicate clicks from starting parallel saves.
- Library offset pagination stops early if the service repeats a full page with no new records; it no longer runs the same page up to the safety limit.
- Playlist realtime/focus updates are coalesced and pending reload timers are canceled on cleanup.
- Support inbox refreshes use request versions and an immediate reply lock so stale loads and double-clicks cannot interfere with an active reply.

Validation after this continuation: 79/79 suites, TypeScript, ESLint, and production build passed. New behavioral cases cover ignored/lost writes, owner-only notification reads, read-all batching/cutoff, grouped release saves, late release lookup races, withdrawn releases, and stalled library pagination. Existing live-browser verification limits remain unchanged. No live notifications were sent or user records modified during testing.
